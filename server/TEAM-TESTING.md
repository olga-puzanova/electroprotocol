# Переход ПСГИ к испытаниям бригадой

Статус на 17.11.2026: опубликованное приложение хранит заявки локально. Подготовленный сервер обслуживает чат и ИИ; синхронизация рабочих данных ещё не реализована и сервер не размещён.

## Предлагаемая схема

- Небольшой сервер в России с HTTPS, отдельными учётными записями и общей базой.
- Заявки, протоколы, журналы, справочники, месячные задания и отметки ознакомления — записи базы с версиями.
- Фото и PDF — закрытое файловое хранилище, доступ после проверки прав.
- На телефоне остаются локальные данные и очередь изменений для работы без связи.
- Яндекс Диск может хранить резервные копии через сервер. Общий токен Диска нельзя включать в публичный код приложения или раздавать сотрудникам.

Конкретный хостинг, конфигурация и бюджет пока не выбраны. Ничего платного не подключено. Альтернатива — инфраструктура Yandex Cloud: виртуальная машина и закрытое объектное хранилище.

## Что требуется реализовать перед общим тестированием

1. Вход по серверной учётной записи; роль и имя определяет сервер, а не переключатель в браузере.
2. Серверная проверка прав: начальник выдаёт задания, назначенные исполнители и ответственный руководитель работают с активной заявкой; завершённые результаты доступны бригаде, изменения протоколируются.
3. Перенос локальных записей через предварительный просмотр и резервную копию. Совпадение UUID и версий не создаёт дубликатов.
4. Постоянная очередь отправки, уникальный идентификатор операции и подтверждение сервера. Надпись «Отправлено» появляется только после подтверждения.
5. Защита от одновременного редактирования: проверка исходной версии, раздельные результаты по испытаниям и явное разрешение конфликтов без молчаливой перезаписи.
6. Удаление с возможностью восстановления, история действий, резервные копии базы и файлов; проверка восстановления на отдельном экземпляре.
7. Ограничение размеров загрузки, защита файлов и независимость рабочих данных от доступности ИИ.

## Приёмочная проверка на двух устройствах

Вначале использовать тестовую бригаду и тестовые заявки.

1. Начальник на первом устройстве создаёт заявку. Назначенный сотрудник и ответственный руководитель видят её на втором; посторонний не видит активную заявку.
2. Сотрудник отключает интернет, заполняет измерения и добавляет фото. После закрытия и открытия приложения всё остаётся. После подключения очередь отправляется один раз.
3. Начальник видит измерения, возвращает протокол с комментарием; сотрудник получает комментарий, исправляет и отправляет повторно.
4. Два сотрудника меняют одну исходную версию: приложение показывает конфликт и сохраняет обе редакции для разбора.
5. Завершённый протокол доступен остальным сотрудникам; номер после регистрации добавляется без потери измерений.
6. Проверяются PDF, отметки ознакомления, журналы, месячные задания, выход из аккаунта и попытка чужого доступа по прямой ссылке.
7. Создаётся резервная копия и проводится фактическое восстановление на отдельной базе.

Только после этих проверок переносить действующую бригаду. Наличие сайта на GitHub Pages само по себе не означает готовность общей базы.
