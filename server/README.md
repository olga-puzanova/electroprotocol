# Сервер чатов ПСГИ

Подготовлен для отдельного размещения. **На GitHub Pages сервер не запускается.** Автоматическая передача заявок, журналов и протоколов между устройствами в этот сервер пока не входит; через сервер работают только общий чат и ИИ-помощник.

Требуется Node.js 24 или новее и постоянный диск для SQLite. Зависимости npm не нужны. Перед первым запуском администратор задаёт переменные окружения:

- `PSGI_ADMIN_PASSWORD`: собственный пароль первого начальника, от 12 символов, без значения по умолчанию.
- `PSGI_ADMIN_LOGIN`: логин начальника, по умолчанию `admin`.
- `PSGI_DATABASE`: путь к SQLite вне публичной папки сайта. По умолчанию `data/psgi.sqlite` относительно папки запуска.
- `PSGI_ALLOWED_ORIGINS`: адреса приложения через запятую. Для текущего приложения: `https://olga-puzanova.github.io`.
- `PSGI_HOST`: по умолчанию `127.0.0.1`; для контейнера `0.0.0.0`.
- `PORT`: по умолчанию 8787.

Запуск из этой папки: `node server.mjs`. Публичный адрес должен использовать HTTPS через обратный прокси. Пример Caddyfile:

```text
psgi.example.ru {
  reverse_proxy 127.0.0.1:8787
}
```

Домен в примере нужно заменить своим. Не открывать файл базы и резервные копии через веб-сервер. Для Docker собрать образ из этой папки, подключить постоянный том к `/data`, передать переменные окружения и опубликовать порт только для обратного прокси. Настроить регулярное резервное копирование SQLite с учётом WAL (через SQLite backup API либо после штатной остановки).

В ПСГИ открыть «Чат → Подключение», сохранить адрес HTTPS и войти. Начальник создаёт отдельные учётные записи сотрудников. Пароли хранятся с scrypt и солью, сессии ограничены восемью часами; в базе сохраняются хеши токенов. Токен браузера хранится только в sessionStorage, без записи в заметки или резервные копии приложения. Получатель видит сообщения после обновления/опроса сервера; метка «На сервере» не означает, что человек прочёл сообщение.

## ИИ-помощник

Выбрать доступного провайдера ИИ и задать на сервере:

- `AI_API_KEY`: ключ сервиса (только переменная окружения сервера).
- `AI_BASE_URL`: базовый адрес API; по умолчанию `https://api.openai.com/v1`.
- `AI_MODEL`: имя модели; по умолчанию `gpt-5-mini`.
- `AI_PROTOCOL`: `responses` (по умолчанию) либо `chat-completions` для совместимого провайдера.
- `AI_REQUESTS_PER_HOUR`: лимит запросов одного сотрудника, по умолчанию 15.

Нужны действующий доступ, поддержка региона и бюджет выбранного сервиса. Без ключа общий чат работает, а ИИ сообщает, что сервис не подключён. Внешнему сервису передаются введённые вопросы и до 12 последних сообщений этого диалога; база измерений и паспорта автоматически не загружаются. Помощник объясняет интерфейс и помогает ориентироваться в документации. Он не подтверждает допуск к работе и не заменяет утверждённые методики.

API: `GET /health`, `POST /login`, `POST /logout`, `GET/POST /users` (начальник), `GET/POST /messages`, `POST /assistant`. Повтор POST сообщения с тем же UUID и текстом не создаёт дубликат. Подмена автора клиентом игнорируется: автор берётся из сессии.

Документация: [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create), [Node.js SQLite](https://nodejs.org/api/sqlite.html).
